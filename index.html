01 — OVERVIEW

このデバイスは何か

胸（鎖骨下）に下げる小型デバイス。装着者本人の声をクリアに録り、対面の相手の声を分離して文字起こしする。音声処理はスマホ側、AI連携はクラウド（OpenAI Realtime）で行う。

GOAL

🎤 2つの声を分けて録る

上から来る「自分の声」と、前から来る「相手の声」を2マイクで分離。会話メモ・対面通訳に使う。

FORM

📐 40×30×10mm の縦長

胸に縦向きで下げる。縦長を活かしてマイクを上下に最大間隔で配置できる。

SYSTEM

🔗 ESP32-S3 → BLE → スマホ

デバイスは収音と送信に専念。重い処理はスマホとクラウドが担当。サーバーレス。

03 — RATIONALE

なぜマイクを「上＋下」に置くのか

分けたいのは「上から来る自分の声」と「前から来る相手の声」。縦に並べると、この2方向がちょうど直交し、2マイクで最もきれいに分離できる。

自分＝エンドファイア／相手＝ブロードサイド。この直交関係が2マイク分離の理想形。

↕ 最長ベースライン

縦40mmは筐体の最長寸法。間隔が広いほど低い周波数（声の芯）まで方向が効き、分離が安定する。

🎯 軸が目的に一致

「上 vs 前」という分けたい方向と、マイクの縦軸がぴったり重なる。斜めや左右配置より素直に効く。

↔ 左右定位は捨てる

縦配置は「相手が左右どちらか」は分からない。1対1の文字起こしが主用途なので問題なし。

04 — COMPETITOR COMPARISON

他社マイク構成との比較（DJI / Anker / PLAUD）

大きく2系統ある。クリップ式ワイヤレスマイク（DJI・Anker）は口元に着ける近接型で単一マイク＋DSP。ウェアラブルAIレコーダー（PLAUD）は離れた話者も録るためマイクアレイ＋ビームフォーミング。本機は後者の系統。

📎 クリップ式は別カテゴリ

DJI・Ankerは口元に着ける近接型。音源が近くSN比が高いので単一マイク＋DSPで足りる。「自分の声」専用。

🧠 PLAUDが本機の同類

離れた話者も録るウェアラブルはマイクアレイ＋ビームフォーミングが必須。NotePinは2、Pro は4マイク。

🦴 VPU／骨伝導は実在の正解

PLAUD Note Pro は4MEMS＋VPU（接触センサー）を採用。本機の背面骨伝導案は業界でも使われる手法。

05 — SYSTEM ARCHITECTURE

システム構成

デバイスは収音と送信に専念。スマホが中継・分離し、AIはクラウド。既存の Wiz アプリ（Flutter）のパイプラインをそのまま拡張できる。

解決 帯域

現状1ch ADPCMで ≈64kbps。2chでも ≈128kbps でBLEに余裕。生音声を送る必要はない。

解決 スピーカー無し

アプリは「再生特性が無い場合はスマホスピーカーへフォールバック」を実装済み。そのまま動く。

既存 省電力 VAD

Autoモードの無音検知を流用し、発話時だけ送信。idle 1–2mA / 1時間で deep sleep。

07 — OPEN DECISION

残る論点：2ストリームの行き先

OpenAI Realtime の入力はモノラル1本。2マイクで分離した「自分」「相手」をどう振り分けるかだけ決めれば、要件は確定する。

A

2系統に振り分け

話者ラベルが綺麗
  • 自分の声 → Realtime（会話 / 通訳・現状どおり）
  • 相手の声 → transcription（Whisper等）
  • 「誰が何を言ったか」を正確に記録できる
  • 実装はやや増える（2系統管理）
B

1本にmixして渡す

実装が軽い
  • 分離後にmixして Realtime へ1本で渡す
  • 既存パイプラインの変更が最小
  • 話者分離はAI任せ（精度は環境次第）

補足：ADPCMの量子化ノイズはchごとに独立のため深いヌルは作りにくい。上下の大きなレベル差＋背面の骨伝導センサーで「自分／相手」を判定する方式が、ADPCM前提では最も堅実。
既存の翻訳モード（対面通訳 英↔日）は元々両者の声が必要なので、この2マイク設計は通訳と文字起こしの両方を強化する。

① ルーティング

A案 / B案 を決定する。

② 骨伝導センサー

採用するか（話者判定の堅牢性が大きく変わる）。

③ 稼働時間目標

連続何時間か → 電池容量を確定する。
